복잡한 경험 정리를 시각적인 마인드맵과 검증된 STAR 기법으로 더 완벽하게 만듭니다.

### 나만의 경험을 모아 정리하는 개인 마인드맵
![freecompress-화면 기록 2026-02-23 오전 3 00 38](https://github.com/user-attachments/assets/58d75fcf-3b29-4d68-85d5-a5502d124835)

🧠 내 생각을 시각화하는 커스텀 마인드맵
"단순한 기록을 넘어, 경험의 연결고리를 찾습니다."

나만의 독립된 브레인스토밍: 개인 마인드맵 공간에서 누구의 방해도 받지 않고 나만의 소중한 경험과 사례들을 자유롭게 펼쳐보세요.

직관적인 히스토리 정리: 산발적으로 흩어져 있던 프로젝트와 에피소드들이 하나의 지도로 연결되는 과정을 경험할 수 있습니다.

<br />

### 다 같이 정리하는 팀 마인드맵
![Adobe Express - 화면 기록 2026-02-23 오전 4 05 40 (online-video-cutter com) (1)](https://github.com/user-attachments/assets/d7376794-7ee8-4ce6-840d-569dfb3c4fe2)

🤝 실시간으로 소통하는 팀 협업 마인드맵
"함께했던 프로젝트, 기억의 조각을 같이 맞춰보세요."

실시간 공동 편집: 링크 공유 한 번으로 팀원들을 초대하세요. 서로의 마우스 포인터와 편집 노드를 실시간으로 확인하며 생동감 있게 협업할 수 있습니다.

집단지성으로 완성하는 회고: 팀 프로젝트의 성과와 에피소드를 동료들과 함께 정리하며, 놓치기 쉬운 세세한 디테일까지 완벽하게 기록하세요.

<br />
<br />

### 마인드맵의 노드와 연결되는 STAR 정리

<img width="1728" height="1081" alt="image" src="https://github.com/user-attachments/assets/0f964638-f9b7-418f-add6-e921b5457cd0" />

✍️ 성과를 증명하는 STAR 에피소드 보관함
"마인드맵에서 곧바로 이어지는 강력한 스토리텔링"

글로벌 스탠다드 STAR 기법: 미국 MBA와 국내 취업 시장에서 검증된 STAR(Situation, Task, Action, Result) 프레임워크를 적용했습니다.

유기적인 데이터 연결: 마인드맵의 각 노드에 STAR 기반의 상세 에피소드를 바로 연결하세요. 막막했던 자기소개서와 면접 준비가 훨씬 쉬워집니다.

💡 STAR 기법이란?
상황(S)과 과제(T)를 분석하고, 본인이 취한 행동(A)과 그에 따른 결과(R)를 논리적으로 구성하여 자신의 역량을 가장 효과적으로 어필하는 작성법입니다.

## 🤝 협업 전략

### 🌿 브랜치 전략

> `main → dev → feature` 구조를 사용합니다.

```
main
 └── dev
      └── feature/#이슈번호/작업내용
```

#### 1️⃣ 브랜치 생성 원칙

* 모든 브랜치는 **이슈에서 생성**
* 작업 단위 = 이슈 1개 = 브랜치 1개
* 작은 단위로 쪼개어 작업 (충돌 최소화)

#### 2️⃣ 브랜치 네이밍 규칙

```
type/#이슈번호/영어_작업_내용
```

예시

```
feat/#12/fe_init
fix/#7/token_expire
refactor/#20/user_logic
```

#### 3️⃣ Merge 규칙

* `feature → dev`
* `dev → main`
* 최소 **2명 approve**
* approve 받은 인원 중 1명이 merge (유동적)

### 🔗 분업 전략

#### 📌 1. 독립 작업 우선

* 의존성이 없는 작업부터 병렬 진행
* API 명세, DTO 구조 등은 먼저 확정

#### 📌 2. 의존 작업 처리 방식

* 선행 작업이 필요한 경우:

  * 인터페이스 / 명세 먼저 정의
  * Mock 데이터 기반 개발 진행
* PR로 빠르게 공유하여 병목 최소화

#### 📌 3. 충돌 방지 전략

* dev 브랜치 수시로 rebase
* 대규모 리팩토링은 사전 공유
* 공통 도메인 수정 시 팀원과 먼저 논의


### 💬 커밋 규칙

#### 커밋 메시지 형식

```
type: 한글 메시지
```

#### 커밋 타입

| type     | 설명     |
| -------- | ------ |
| feat     | 새로운 기능 |
| design   | CSS 수정 |
| refactor | 리팩토링   |
| fix      | 버그 수정  |
| chore    | 설정/잡일  |
| docs     | 문서     |
| test     | 테스트    |

# 🌟 팀 그라운드 룰

## 🎯 우리의 목표

* 🏆 **1등 상 받기**
* 😎 **싸우지 말기**

## 🗣 말하기 규칙

* 이쁘게 말하기 (용용체)
* 반론/반대 의견 제시할 때:

  * “2얏!” 외치고 손들기
  * 용용체로 말하기
  * 반드시 **대안 또는 이유 제시**
* 무턱대고 반대 금지
* 궁금한 건 사소해도 바로 물어보기
* 모르는 건 바로 공유하기
* 아프거나 늦거나 등 상황 발생 시 단톡 공유
* “주말에 당연히 해야죠” 같은 말 금지
* 야근을 당연하게 생각하지 않기

  * 자기 일은 책임감 있게
  * 못 끝낸 팀원 돕기
* 슬랙/카톡 공지에 최소 1개 이모지 반응
* 회의에서는 존댓말 사용

## 💫 회의 규칙

* 회의록 미리 읽어오기
* 회의록 돌아가면서 작성 (AI 요약 가능)
* 40분 회의 후 10분 휴식

## 🏃 도망 규칙

* 자리 비울 경우 “n분 숨겠습니다” 선언

## 🕙 개발 스크럼

### ⏰ 시간

* 안부 묻기: 10:10 ~ 10:30
* 스크럼: 10:30 ~ 10:50 (인당 5분)

### 📌 내용

* 이전 스크럼 이후 무엇을 했는지
* 다음 스크럼까지 무엇을 할지
* 예상 소요 시간 포함

### 💬 안부 시간 주제

* 오늘의 컨디션 점수
* 다 지쳤으면 게임 한 판 or 명상(을 가장한 취침)
* 점심 뭐 먹지
* 재밌는 이야기 등

### 🚶 산책 시간 (optional)

* 15:30

## 🍪 설명 못하는 코드 작성 시

> 간식 헌납

### 🎯 의도

* 본인도 설명할 수 없는 코드 작성 금지
* 이유 있는 개발
* 남에게 피해 주지 않는 코드

## ⛔ 위반 시 벌칙 (택 1)

* 엉덩이로 이름 쓰기
* 실행 전 최후의 발언 후 구제 여부 선택
* 궁서체/필기체 금지 (정자만 허용, 줄임말 금지)

  * 폰트는 디자이너팀 지정
* 팀원들에게 원하는 음료 쏘기
